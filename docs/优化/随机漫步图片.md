[cosmos.so](https://www.cosmos.so/)（一个面向设计师和创作者的灵感收集平台）的“多图无限展示”（无限流、空间感网格）效果，并非依赖单一的开箱即用开源组件，而是由其背后的开发团队（主要由 Airnauts 代理开发）构建的**高度定制化技术栈**。

通过结合该平台的技术工程文档和设计分析，其多图无限展示的技术框架由以下几个核心层组成：

### 1. 视图与核心框架层：React + Next.js

Cosmos 的前端核心框架是基于 **React** 和 **Next.js** 构建的。  

- **虚拟化与状态管理**：无限滚动的瀑布流/画布往往伴随着庞大的 DOM 节点数量。React 负责底层的数据状态管理和组件生命周期。
- **自定义布局引擎**：Cosmos 没有使用传统的规则瀑布流（如 `react-masonry-css`），因为它的卡片是带有“散落感”的（不同的缩放比例、轻微旋转、Z轴空间深度）。这就要求网格系统必须是自研的，以精确计算每张图片的绝对定位（Absolute Positioning）。

### 2. 动画与空间交互引擎：GSAP (GreenSock)

Cosmos 画布上最惊艳的“3D空间感”和流畅的悬浮卡片交互，核心是由 **GSAP (GreenSock Animation Platform)** 驱动的。

- **空间深度计算**：在平面的 2D 画布上，利用 GSAP 动态操控元素的 `transform`（如 `scale`、`rotate`、`translate3d`），让图片在滚动或鼠标交互时产生视觉差和景深效果。
- **平滑无限滚动**：接管浏览器的原生滚动行为（可能结合了类似 Lenis 或 GSAP ScrollTrigger 的平滑滚动方案），确保在大量图片加载并插入 DOM 时不发生卡顿或掉帧。

### 3. 高性能数据检索层：Qdrant (向量数据库)

无限图片流需要极其强悍的后端检索引擎来实时“喂”数据，尤其是在用户进行颜色过滤或相似度匹配时。

- Cosmos 放弃了传统的数据库方案（如 Postgres + pgvector），转而使用了 **Qdrant Cloud**。  
- 当你在无限画布中滑动或通过多维条件（例如：“柔软的光线摄影” + 某个精确的十六进制颜色代码）进行检索时，Qdrant 能够在**亚秒级**延迟内，通过混合检索（文本向量化 + 基于 CIELAB 色彩模型的颜色向量）实时返回下一批图片流供前端渲染。

### 4. 后端与底层基础设施：.NET 8 + AWS

- 支撑前端海量图片数据并发请求的，是基于 **.NET 8** 构建的高性能后端 API。
- 图片的存储、CDN 加发、以及基础设施由 AWS 和 Terraform 承载，以保证全球不同地区访问高分辨率图片时的加载速度。

**总结来说：**

如果你想要复刻 `cosmos.so` 这种极具空间感的多图无限展示效果，技术选型的公式大致为：**React / Next.js（基础视图与组件） + 自研绝对定位的虚拟列表（剔除不可见节点以防卡顿） + GSAP（处理三维视差、随机旋转、平滑进场动画） + 高性能的向量检索后端（如 Qdrant 提供源源不断的精准关联图片流）**。
