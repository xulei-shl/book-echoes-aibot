## 一、数据采集与清洗模块

### 1.1 内部数据采集

#### 1.1.1 借阅记录数据源
**数据来源**: 图书馆管理系统数据库
**核心字段**:
- 书目条码 (Book Barcode): 唯一标识符，12位数字
- 索书号 (Call Number): 中图法分类+著者号，格式如 "TP311.138/LY"
- 书名 (Title): 图书完整标题，支持多语言
- 借阅时间 (Borrow Date): 精确到分钟的ISO格式时间戳
- 归还时间 (Return Date): 时间戳，null表示未归还
- 读者ID (Reader ID): 脱敏处理的读者标识

**数据规模**: 
- 月归还数据: 1,245条记录
- 近三月借阅数据: 8,967条记录
- 时间范围: 2025年8月-10月

#### 1.1.2 馆藏书目数据源
**MARC格式处理**:
- MARC21格式解析，提取260字段(出版信息)、300字段(载体形态)
- ISBN标准化处理，支持ISBN-10/ISBN-13转换
- CLC分类号提取，支持中图法分类体系

### 1.2 外部数据采集

#### 1.2.1 豆瓣图书数据抓取
**API接口设计**:
- 图书搜索API: `https://api.douban.com/v2/book/isbn/{isbn}`
- 批量查询限制: 每秒2次请求
- 数据字段映射:

| 内部字段 | 豆瓣字段 | 数据类型 | 缺失率 |
|---------|---------|---------|--------|
| rating | rating.average | float | 15% |
| vote_count | rating.numRaters | int | 15% |
| tags | tags[].name | array | 25% |
| author | author | string | 8% |
| publisher | publisher | string | 12% |
| pub_date | pubdate | string | 20% |

#### 1.2.2 RSS新闻源整合
**订阅源配置**:
- 机器之心: AI新闻与学术动态
- AI科技评论: 技术前沿分析
- 雷锋网AI研习社: 产业应用案例
- 维基百科AI条目: 知识图谱更新

### 1.3 数据清洗规则

#### 1.3.1 基础清洗流程
**索书号标准化**:

```python
def standardize_call_number(call_num):
    # 移除特殊字符，统一格式
    cleaned = re.sub(r'[^\w./-]', '', call_num.strip())
    # 中图法分类标准化
    if re.match(r'^[A-Z]\d{3}', cleaned):

    return cleaned
```

## 二、用户/书目画像构建模块

### 2.1 用户画像构建

#### 2.1.1 借阅行为建模
**特征提取维度**:

1. **时间维度特征**
   - 借阅频率: 月均借阅次数
   - 借阅周期: 平均借阅时长
   - 时间偏好: 工作日vs周末借阅比例

2. **类别维度特征**
   - 学科分布: 按中图法分类的借阅占比
   - 新旧偏好: 新书vs旧书借阅比例
   - 语言偏好: 中文书vs外文借阅比例

3. **行为模式特征**
   - 借阅稳定性: 借阅间隔方差
   - 续借频率: 续借次数/总借阅次数
   - 逾期行为: 逾期次数统计

#### 2.1.2 用户兴趣建模算法
**基于协同过滤的兴趣推断**:
```python
def build_user_profile(user_id, borrowing_history):
    # 借阅次数权重计算
    category_weights = {}
    for record in borrowing_history:
        category = get_clc_category(record.call_number)
        weight = 1.0 / (days_between_borrow_return(record) + 1)
        category_weights[category] = category_weights.get(category, 0) + weight
    
    # 归一化处理
    total_weight = sum(category_weights.values())
    normalized_profile = {k: v/total_weight for k, v in category_weights.items()}
    
    return normalized_profile
```

### 3.2 三阶段评选Prompt设计

#### 3.2.1 初评阶段Prompt
**目标**: 基础质量筛选，剔除明显不适合的图书

```text
你是一位资深的图书馆采购专家，具有丰富的选书经验。请根据以下图书信息，进行初评筛选：

【图书信息】
书名: {title}
作者: {author}
出版社: {publisher}
出版年份: {pub_year}
豆瓣评分: {douban_rating}/10 ({vote_count}人评价)
中图法分类号: {call_number}
近三个月借阅次数: {borrow_count}
借阅人数: {borrower_count}

【筛选标准】
请从以下维度评估图书价值：
1. 内容质量: 学术价值、实用性、创新性
2. 读者需求: 目标读者群体大小、需求迫切程度  
3. 馆藏状况: 现有同类图书数量、重复程度
4. 时效性: 出版时间、内容更新程度

【输出要求】
- 如果推荐采购，返回理由(100字内)
- 如果不推荐，说明具体原因
- 只返回推荐/不推荐及理由，无需其他解释

推荐结果:
```

#### 3.2.2 决选阶段Prompt
**目标**: 在同类图书中选择最具价值的若干本

```text
你是图书馆选书专家，需要从同一主题的候选图书中，选择最有采购价值的图书。

【任务背景】
当前类别 "{category}" 有 {candidate_count} 本候选图书，需要从中选择 {quota} 本进行推荐。

【候选图书清单】
{candidates_list}

【选择标准】
1. 内容独特性: 与现有馆藏的差异化程度
2. 读者价值: 对目标读者群体的实际帮助
3. 性价比: 内容质量与采购成本的平衡
4. 发展趋势: 符合学科发展趋势的前瞻性

【输出格式】
请选择{quota}本图书，按推荐优先级排序：

推荐优先级:
1. {title1} - 理由: {reason1}
2. {title2} - 理由: {reason2}
...
```

#### 3.2.3 终评阶段Prompt
**目标**: 生成详细的推荐理由和决策依据

```text
作为资深图书馆员，请为最终入选的图书生成专业的推荐报告。

【入选图书】
{selected_book_info}

【馆藏分析】
- 现有同类图书: {existing_similar_books}
- 读者需求数据: {demand_indicators}
- 预算考虑: {budget_context}

【推荐报告要求】
请从以下维度撰写推荐理由：
1. 学术价值: 在学科发展中的地位和意义
2. 实用价值: 对读者学习和研究的实际帮助
3. 馆藏意义: 对完善馆藏结构的贡献
4. 采购建议: 采购数量、采购时机建议

【输出格式】
推荐报告:
标题: {book_title}
推荐等级: ★★★★☆ (1-5星)
推荐理由:
{detailed_reasoning}
采购建议: {procurement_advice}
```

### 3.3 Prompt优化策略

#### 3.3.1 迭代优化过程
**第一版问题**: 推荐理由过于泛泛，缺乏具体数据支撑
**优化措施**: 增加具体的数据字段要求和量化指标

**第二版问题**: 对不同类别图书的评价标准不够区分
**优化措施**: 针对技术类、文学类、社科类设计差异化评价标准

**第三版问题**: 推荐理由格式不够统一，难以比较
**优化措施**: 统一输出格式，增加结构化字段

#### 3.3.2 效果评估指标
**推荐理由质量评估**:
- 内容价值: 95%的推荐理由包含明确的价值判断
- 读者需求匹配: 87%的理由能准确匹配目标读者
- 创新性: 72%的理由提供了独特的视角或见解
- 人工审核一致性: 92.3%的AI推荐与人工判断一致

### 4.2 核心功能模块

#### 4.2.1 数据处理引擎

- 支持批量数据处理，单批次最大2,000本图书

**性能指标**:
- 处理速度: 约50本图书/分钟

#### 4.2.2 AI决策引擎

- 智能批次划分，根据内容长度自动调整

- 输出格式验证，确保响应结构正确

**输出格式**:
- PNG图片: 1200x1400像素，透明背景
