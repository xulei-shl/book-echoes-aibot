## 4. 根因分析

### 4.1 直接原因

DuckDuckGo HTTP 请求通过代理 `http://127.0.0.1:7890` 访问 `api.duckduckgo.com` 时超时，返回 `ETIMEDOUT` 错误。

### 4.2 代码回退逻辑问题

```typescript
// duckduckgoResearcher.ts:284-294
} catch (error) {
    logger.error('所有方式都失败了', { error });
    
    // 提供模拟数据作为最后的回退，确保功能可用
    const fallbackSnippets: DuckDuckGoSnippet[] = [
        {
            title: '网络连接问题',
            url: 'https://duckduckgo.com',
            snippet: `无法连接到外部搜索服务...`,
            raw: { error: 'Network connection failed' }
        }
    ];
    
    return fallbackSnippets;  // ← 问题：当作正常结果返回
}
```

**问题**: 这个"错误占位数据"被当作正常结果返回，前端无法区分"真结果"和"假数据"。

### 4.3 前端渲染逻辑

```typescript
// DeepSearchDraftMessage.tsx:175
{searchSnippets.map((snippet, index) => (
    <div>
        <h5>{snippet.title}</h5>      // ← "网络连接问题"
        <p>{snippet.snippet}</p>     // ← 错误信息
        <a href={snippet.url}>...</a> // ← https://duckduckgo.com
    </div>
))}
```

前端直接渲染 `searchSnippets`，没有检查是否是错误数据。

## 5. 解决方案建议

### 方案 A: 增加更长的超时时间 (推荐)

修改 `duckduckgoResearcher.ts` 超时时间，或在 `webSearchService.ts` 中增加重试逻辑。

### 方案 B: 前端区分错误数据

在 `DuckDuckGoSnippet` 类型中增加标记字段，或检查 `raw.error`：

```typescript
// DeepSearchDraftMessage.tsx
const isErrorPlaceholder = (snippet) => snippet.raw?.error === 'Network connection failed';

{searchSnippets.filter(s => !isErrorPlaceholder(s)).map(...)}
```

### 方案 C: 配置其他搜索方式

- 使用其他代理服务
- 部署自有 MCP DuckDuckGo 服务
- 使用其他搜索 API (Bing, Google 等)
